# Vialogue：會動的海灘與輕互動

日期：2026-10-20

狀態：使用者已於 2026-10-20 核准本規格，進入實作計畫。本文描述下一輪要做的版本，不代表功能已完成。

## 1. 這輪要達成的體驗

玩家願意留在海邊，寫信、讀信、等待，也看著光線與潮水變化。旁邊的旅人偶爾發出表情，玩家可以回應；在沙上隨手畫的痕跡，會被時間與浪帶走。介面以隨身物件和場景操作呈現。

使用者已明確提出：場景要有動態與沉浸感、頭頂動態表情貼、會消失的沙灘塗畫，以及更像遊戲的按鈕和寫信介面。已同意延續像素人物，先以 PixiJS 製作一片完整的小海灘。

本輪沿用本機試玩。示例旅人的反應用於體驗互動，不代表真人連線。正式瓶子規則以 `VIALOGUE-CONCEPT.md` 為準；新增沙畫屬使用者本次同意的試作範圍，產品文件原列為未來項目，實作交付時應同步記錄此次範圍調整。

## 2. 交付範圍與完成條件

| 項目 | 本輪交付 |
|---|---|
| 環境 | 分層天空、雲、海面反光、推進與退去的浪花、偶爾飛過的海鷗 |
| 日夜 | 依裝置當地時間平滑變色，包含晨光、白天、日落、夜色與岸邊燈光；試玩可預覽各時段 |
| 表情互動 | 四款有出現、停留、退場動畫的頭頂貼圖，可主動發出及回應示例旅人 |
| 沙畫 | 滑鼠與觸控畫沙痕，乾沙上的痕跡隨時間淡去，濕沙上的痕跡受實際浪花範圍逐段抹除 |
| 遊戲介面 | 小型工具入口、角色旁表情選單、可拾起的瓶子、展開的信紙與信冊 |
| 原有流程 | 保留寫信、照片、冷卻、草稿續寫與取回、持瓶期限、接續、返航、收藏和單分頁保護 |
| 可開啟性 | 根目錄入口不變，直接開 HTML 與本機 HTTP 均可用；遊玩時不連 CDN |

本輪不包含 Google 登入、真人房間、伺服器配送、公開塗畫同步、全部 75 種造型的動態換裝、完整各方向走路，以及任務、積分或物品經濟。

## 3. 技術選擇與程式邊界

使用 **PixiJS 8.20.1、WebGL renderer**，固定版本並附 MIT 授權與來源紀錄。延續原生 JavaScript，瀏覽器端以本地傳統 script 載入，無須安裝套件或建置才能遊玩。

選擇比較：現有 Canvas 可延續，但每個場景物件的繪製與互動需手動管理；PixiJS 的場景樹適合此輪分層、貼圖、遮罩與指標互動；Three.js 的立體鏡頭與空間能力留給未來確定需要立體世界時使用。本輪維持固定視角與前後景深。

將 `prototype/app.js` 中的呈現職責拆出，避免新效果繼續堆入同一個檔案：

| 邊界 | 職責與輸入輸出 |
|---|---|
| `model.js` | 保留信件與持瓶規則；環境動畫、發表情、畫畫不呼叫信件續期 |
| 場景資料 | 圖層、世界尺寸、錨點、導航、濕沙與可畫範圍、角色與燈光配置 |
| 環境模型 | 輸入時間、經過秒數與可注入亂數，輸出日夜、浪線及海鷗事件；不讀 DOM 或 localStorage |
| 輕互動模型 | 管理表情事件、冷卻、沙畫筆跡、取樣與消退；使用世界座標，與 renderer 分開 |
| Pixi 場景 | 建立圖層、畫角色與效果、世界／螢幕座標轉換、命中測試與鏡頭 |
| 介面與整合 | 將玩家操作轉為命令，保留原有保存、圖片處理與視窗焦點；更新可讀取的 DOM 介面 |

場景事件使用短期資料，例如表情的角色 ID、種類、起始時間，以及筆跡的點列、出生時間、剩餘強度。本輪不建立網路 transport 或預先擴充多人服務；事件結構只需讓本機玩家和示例角色共用。

## 4. 場景、美術與座標

- 邏輯世界與橫向構圖使用 1280 × 720，左上為原點，x 向右、y 向下。
- 目前海灘原圖實測 1672 × 941，已包含夕陽、雲、海浪和反光，不能直接當作中性日夜底圖。保留原圖，以它和已確認風格為參考，補製可分層的新場景素材。
- 角色保留 128 × 160 畫布與腳底錨點 `[64,148]`，在世界中按 1:1 顯示，統一倍率縮放、不任意改變頭身比例。PNG 使用 nearest 取樣，位置取整以減少像素閃動。
- 前後順序：天空與日月 → 遠景島嶼與燈塔 → 海面及反光 → 沙地與沙痕 → 近岸浪花 → 依腳底 y 排序的角色與可拾取瓶子 → 前景岩石 → 頭頂表情 → DOM 工具與信紙。
- 岩石和浪各有獨立遮罩；水面位移效果只套在水域，不能使人物、地面、燈塔或整幅畫面扭動。太陽、倒影和月光須可獨立開關，夜晚不能留下橘色夕陽。
- 海灘的可行走區、岩石障礙、可畫區與濕沙帶依採用場景描出，共用一份 `map_bundle.v2` 與環境設定。導航檢查與遊戲使用同一份幾何，角色腳底不能穿越岩石或走入海中。
- 導航以腳底橢圓為碰撞範圍，`actorRadius:9`、`ySquash:0.5`；不以完整 128 × 160 圖片外框阻擋。移動路徑的每一段都要有效，不能只檢查落點而穿過障礙物。
- 主角出生點沿用 `[640,610]`，讀取舊位置時檢查是否仍可站立；失效才移回出生點，不清除信件。濕沙互動區必須能由出生點走到。
- 手機鏡頭以角色為中心裁切，限制於世界邊界；天空與遠景須覆蓋裁切後畫面，工具與表情面板另按手機排版，不能靠縮小整張桌面介面適配。

美術以內建 ImageGen 補圖，來源標記為 `host_image`，沿用素材標記為 `existing`；保留提示、原始輸出、處理紀錄與 SHA-256。場景、海鷗和表情貼的新增素材分開保存，不能從未採用的歷史人物圖反推角色版本。人物仍使用 catalog 與已採用的 PNG；頭頂貼圖不等於角色臉部表情已完成。

本輪人物待機沿用已接入試玩的坐姿影格，呼吸與眨眼錯開時間。站姿移動仍沿用目前素材，不把它驗收為完整走路動畫。

## 5. 自然變化的節奏

| 效果 | 初始節奏與限制 |
|---|---|
| 海面 | 小幅局部位移與反光變化，遠海較慢，近浪較明顯；不新增滿畫面粒子 |
| 岸浪 | 每輪約 7～12 秒，推進較快、退去較慢；相鄰浪段錯開，浪線與沙痕消退使用同一時間來源 |
| 雲 | 緩慢橫移，離開範圍後在畫面外接續，沒有可見瞬移接縫 |
| 海鷗 | 首次自然事件在進場後 12～25 秒，後續間隔 35～90 秒；每次 1～3 隻，每隻使用有展翅變化的 PNG 影格 |
| 日夜 | 以當地時間在 05:00 晨光、07:00 白天、16:30 暖光、18:30 暮色、20:00 夜色之間平滑插值，跨午夜連續 |
| 夜間 | 夕陽與日照反光隱去，月光／星點與岸邊小燈顯現；仍保留人物與沙地辨識度 |

日夜是依當地時間安排的美術時段，不取定位、不計算真實天文日出。試玩工具提供晨光、白天、日落、夜晚及加速預覽；它只影響場景時間，不能推進新瓶冷卻、持瓶期限或七天返航。原有信件時間推進工具另保留並清楚命名。

切到背景分頁時暫停場景動畫與示例事件。回來時按真實時間更新日夜與信件期限，不補播大量海鷗或表情；聲音仍由玩家手動開啟，預設關閉。

## 6. 頭頂表情與陪伴

四款先做「揮手、開心、驚訝、陪伴」。點自己的角色或工具列表情圖示，開啟角色旁的小型選單；鍵盤 `E` 可開啟，方向鍵與 Enter 可選擇，Escape 關閉。桌面懸停及手機點選均顯示文字標籤，不能只靠顏色辨識。

表情貼在頭部上方彈出，約 0.2 秒出現、3 秒停留、0.4 秒淡去；每個角色同時一張，新表情替換舊表情，玩家每 3 秒可發一次。貼圖跟著角色移動，面板靠近畫面邊緣時向內調整，不被裁切。

四位現有示例旅人保留為本機角色。他們每隔 20～50 秒有機會發出表情，玩家發表情後，附近角色有機會在 1.5～4 秒後回應；回應只觸發一輪，不讓示例角色彼此無限接力。單一示例角色至少隔 20 秒才再次發表情。使用可注入亂數驗證觸發與未觸發路徑。

小型「本機試玩・示例旅人」標記常駐，初次說明交代本機反應的性質。仍不提供自由文字聊天，也不將海灘角色連結到瓶中信作者。

## 7. 沙灘畫畫

工具列選「畫沙」後，角色留在原地並暫停等信，游標變成筆尖。滑鼠按住或手指拖曳，於角色腳底周圍 120 世界像素、且位於可畫沙地的範圍內留下 2 世界像素寬的沙痕。超出範圍不繼續落筆，也不觸發移動。先用單一沙痕色，不提供貼圖上傳或文字輸入工具。

畫畫期間不拖動鏡頭；觸控不捲動整頁。放開、`pointercancel` 或切換視窗會結束當前一筆。完成按鈕及 Escape 回到移動模式，恢復進入畫畫前的等信選擇；持瓶時先處理或放回瓶子，再進入畫畫模式。

乾沙痕跡保留 90 秒，接著在 30 秒內淡去。濕沙痕跡在浪花經過的區段逐次減淡，兩次完整覆蓋後清除；未被浪碰到的部分按乾沙期限消退。不得只在固定秒數把整筆突然刪掉，讓畫面看起來像被浪抹除。

最多保留 24 筆，每筆最多 256 個經取樣簡化的點；新增超過上限時，最舊的已完成筆跡於一秒內淡出，當前一筆不被截斷。筆跡與表情存在記憶體，重開頁面後消失，不寫進信件儲存資料。

## 8. 遊戲介面與信件呈現

- 進場短暫顯示名稱與一行操作提示後收起，不保留目前佔據天空的大型宣傳標題。
- 平常只保留小型工具：寫信、等信、表情、畫沙、信冊與聲音。圖示採同一組像素／物件風格，保有名稱、焦點狀態與至少 44 CSS px 的觸控命中區。
- 點沙地移動，點人物開互動選單，點瓶子拾起；UI 點擊不穿透到沙地。畫畫模式、信紙開啟時不觸發場景移動。
- 到信以角色附近的瓶子微光與一次短提示呈現；未拆三分鐘的停留時間仍可讀取。送信或放回時讓瓶子朝海面漂離，資料提交在動畫前完成，不等動畫才保存。
- 寫信與讀信使用從畫面下緣展開的信紙，打開時海灘維持清楚可辨、持續動態。去掉全景模糊與厚重白色圓角彈窗外觀；只在必要時加局部遮擋以保文字可讀。
- 旅途、返航、收藏與草稿改為可翻閱的信冊。沿用上一輪的新信續寫、原瓶續寫、過期草稿取回、完整旅途閱讀入口及未讀返航紀錄。
- 信紙保留 DOM textarea、文字選取、圖片放大、label 與焦點管理，容器可沿用原生 dialog 的操作語意，但完全重做樣式及開關轉場。信紙關閉回到觸發它的按鈕；Escape 收起並保存草稿，不放回仍持有的瓶子。
- 開啟信紙或信冊時先結束當前畫筆並退出畫畫模式，關閉後回到一般移動／坐下狀態；表情選單亦收起，避免隱藏的畫筆仍吃到下一次點擊。收到新瓶只提示，不自動打斷正在寫的新信。
- 手機信紙採接近滿高的直向版面，可在軟體鍵盤開啟後捲動到輸入框與送出鍵。多層圖片視窗關閉後回到原信頁。
- 返航以信冊的低干擾未讀標記與可點入口呈現，保留重開後提醒；不再疊大型網頁卡片遮住場景。

## 9. 載入、保存與退化行為

沿用 `vialogue.local-playtest.v1` 的信件、草稿、收藏、`readReturns` 與 Web Locks；本輪不清空資料，也不把場景預覽時間寫入 `clockOffset`。舊版沒有的新顯示設定採預設值即可。

PixiJS 固定版瀏覽器檔存入本地 vendor，場景 manifest 與貼圖由原始 JSON／PNG 產生可用傳統 script 載入的資源包。WebGL 貼圖由內嵌資料建立，不直接以 `file://` PNG URL 上傳，也不在直接開檔模式下 fetch JSON。這項設計用來保留原有直接開啟入口，須以真實瀏覽器驗證。

重要場景素材載入失敗時顯示可重試的載入訊息，不讓玩家在空白畫面誤操作。WebGL 不可用或 context lost 時暫停場景輸入並顯示恢復／重新開啟選項，先保存草稿；本輪不另做一套 Canvas renderer。信件與照片仍使用原有儲存失敗提示與處理中送出保護。

`prefers-reduced-motion` 時取消彈跳、浪花往返及海鷗飛行，以靜態畫面與簡單表情切換呈現；保留日夜狀態、文字通知與所有信件操作。一般模式限制 DPR 為 2，目標 60 FPS，低畫質選項減少反光與效果更新頻率，保留基本浪線與互動回饋。未實測裝置不宣稱穩定幀率。

## 10. 驗證與交付標準

1. 純模型測試：跨午夜日夜連續、場景時間與信件時間分離、表情冷卻／退場／不接力、乾濕沙消退、筆跡上限、畫畫前後等信狀態恢復、取消指標操作。
2. 地圖檢查：`map_bundle.py validate`、`map_nav.py check` 及實際預覽路線驗證；出生點到乾沙、濕沙與各互動區可達，岩石與海水不可穿越。檢查幾何疊圖與實際美術是否相符。
3. 瀏覽器流程：沿用既有 31 項流程的行為斷言，更新新的 UI 入口；包含草稿續寫、過期取回與剪貼簿、未讀返航、圖片處理、單分頁保護與重載保存。
4. 新互動流程：人物旁選單與頭頂動畫、示例角色回應、畫畫不誤移動、畫畫期間不收新瓶、退出後恢復等信、浪花只抹除覆蓋部分、關閉信紙後回到原活動。
5. 畫面 QA：桌面 1440 × 960 與手機 390 × 844，另檢查 360 px 寬與短高度版面；晨光、白天、日落、夜色各留截圖。夜晚無殘留太陽與金色日照，UI 不遮住主角或關鍵互動。
6. 動態 QA：截取數個已知時點，確認天空、海面、浪、海鷗確實各自變化，而地面／岩石／角色紋理沒有整幅漂動。提供約 15～20 秒實際遊玩錄影，讓使用者判斷節奏與沉浸感。
7. 相容 QA：直接開檔與 HTTP 均驗證；離線時無 CDN 請求，失敗載入與 WebGL 不可用有可讀提示。檢查減少動態模式、鍵盤操作與手機信紙捲動。
8. 美術保護：執行 AGENTS.md 指定的角色 validate、preview 與八項既有測試；新增場景素材另建來源與基準，不替換已確認角色圖。

程式檢查只能證明規則與技術行為；海灘是否有遊戲感、沙畫和表情是否自然、寫信時是否仍覺得留在海邊，須由使用者檢視可玩版本與錄影後確認。交付說明列出仍未完成的角色動作與真人同步範圍。
